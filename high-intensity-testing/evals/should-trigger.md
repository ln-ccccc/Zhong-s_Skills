# 应当触发的输入(should-trigger)

以下输入应加载本 skill。判定时对照 description 的触发词与场景,而非逐字匹配。

| # | 输入示例 | 预期行为 |
|---|---|---|
| 1 | "对这个修复分支做一次全面审查再合并" | 加载 SKILL.md → 走预检(OCR 或降级) → 六步工作法 → 报告 |
| 2 | "按上次审查的方式再查一遍" | 直接按 SKILL.md 流程执行,不重新设计流程 |
| 3 | "这 24 个修复提交验收一下" | 修复批次验收模式:重点跑 T26 声明对照 + 回归墓碑检查 + 权威门 |
| 4 | "里程碑发布前做一轮对抗审计" | 全面模式五阶段 |
| 5 | "这个 bug 修了,帮我确认不会回归" | Prove-It:要求先在旧代码上复红,再固化回归墓碑 |
| 6 | "帮我把这轮发现固化成测试" | 六步第 6 步:契约测试(键集/接线/超时/状态码) |
| 7 | "审查报告里这两条 P1 我觉得是误报" | severity.md:主控复现裁决,共识不替代复现 |
| 8 | "子系统要重构,怎么保证不隐性破坏" | 地雷图注入 + 契约驱动 + 固化测试的组合 |
