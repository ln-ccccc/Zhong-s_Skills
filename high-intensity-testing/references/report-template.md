# 审查报告模板

```markdown
# 审查报告 YYYY-MM-DD(<分支/范围>)

## 一、概述
- 输入:审查基线(main@<sha>) → 目标(<branch>@<sha>),共 N 个提交
- 范围:<模块清单 / 全仓>
- 方法:预检(OCR 委托 / 降级) + 并行子代理拓扑(<N> 个:<模块列表>) + 主控抽查
- 结论一句话:<X 个发现,P0×a / P1×b / P2×c / P3×d,合并建议:…>

## 二、发现清单

| ID | 严重度 | 位置 | 摘要 |
|---|---|---|---|
| F1 | P0 | path/file.py:123 | <一句话> |

### F1 <标题>
- **严重度**:P0(判定理由,对应 severity.md 哪条)
- **位置**:path/file.py:123-130
- **描述**:<失效机制>
- **复现**:<可执行复现步骤/命令,P0/P1 必填>
- **影响**:<业务/数据后果>
- **修复建议**:<最小修复方向>

(逐条展开…)

## 三、回归网固化
每条 P0/P1 对应新增的测试:测试名 + 文件 + 「先红后绿」记录(修复前红/修复后绿的跑法与输出摘要)。

## 四、接受与悬置
- 接受项:<编号 + 接受理由(前提不成立/影响面为零等)>
- 悬置项:<编号 + 重启条件>

## 五、修复台账
| 报告编号 | 修复 commit | 声明 | 实现证据(file:line) | 复验 |
|---|---|---|---|---|
```

填写纪律:证据宁缺毋滥——存疑的不写,写了的都能复现;每条发现独立成段,不合并;修复台账在修复批完成后由主控逐条补齐(T26)。
