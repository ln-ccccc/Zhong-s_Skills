# 失效模式技巧库(T2–T37)

每条 = 失效一句话 + 关键动作一句话,写在原则层(可迁移);项目级实证与具体命令留在各项目自己的 playbook。编号 T2–T30 沿用某项目 playbook 源,T31 起为通用新增(T5 未使用)。

## 十五问触发清单(没有测试思路时逐条自问)

| # | 自问 | 对应技巧 |
|---|---|---|
| 1 | 同一操作**连续跑第二遍**会怎样? | T3 连续运行验证 |
| 2 | 换一批**形态不同**的输入(格式/规模/来源)会怎样? | T4 混合批次抽样 |
| 3 | 输入为空 / 极大 / 非法 / 重复会怎样? | T6 边界值与等价类 |
| 4 | 用**真实业务数据**(而非手工造的数据)跑会怎样? | T7 数据真实性 |
| 5 | 客户端**中途断开 / 超时 / 取消**会怎样? | T8 异常路径 |
| 6 | 依赖的服务**不可用**时,是明确报错还是静默出错? | T8 异常路径 |
| 7 | **两个相同请求同时到达**会怎样? | T9 并发与竞态 |
| 8 | 连续运行一整夜,内存/句柄/磁盘会缓慢泄漏吗? | T10 浸泡测试 |
| 9 | 把依赖进程 **kill -9** 会怎样?能自愈吗? | T11 故障注入 |
| 10 | 这次修复**留下回归测试**了吗? | T12 回归墓碑 |
| 11 | 我是在**真实部署环境**里测的吗? | T13/T19/T22 环境一致性 |
| 12 | 性能优化前,有**分阶段基线数据**吗? | T14 先测量后优化 |
| 13 | 测试过程会把密码/密钥写进日志、截图或临时文件吗? | T15 敏感信息 |
| 14 | 自动化测试失败时,分得清**产品缺陷还是工具限制**吗? | T16 工具限制隔离 |
| 15 | 页面内容超过一屏时**能滚动吗**?滚到底内容完整吗? | T17 满屏滚动验证 |

## 策略层

| ID | 技巧 | 失效 | 关键动作 |
|---|---|---|---|
| T2 | 递进验证 | 单次通过≠批量可用 | 冒烟→小批次(≥3 组,必含上次失败过的输入)→全量,逐级放大 |
| T3 | 连续运行验证 | 状态残留只在第二次暴露 | 修复类改动同输入连跑两遍,第二遍标准与第一遍一致 |
| T4 | 混合批次抽样 | 手工造数太规整 | 混合格式/规模/来源的输入分组抽测 |
| T10 | 浸泡测试 | 泄漏短时数学上不可见 | 长时连续运行,盯内存/句柄/磁盘曲线 |
| T11 | 故障注入 | 容错代码只在真故障时执行 | kill -9 依赖进程/断网/磁盘满,验**恢复能力**而非"没崩" |

## 用例设计层

| ID | 技巧 | 失效 | 关键动作 |
|---|---|---|---|
| T6 | 等价类+边界值 | 缺陷在边界聚集 | 每个数值参数取:最小、最小+1、正常、最大-1、最大、越界 |
| T7 | 数据真实性 | 隐含假设不体现在造数里 | 测试数据从权威资产生成,格式分叉每类至少一条真实样本 |
| T8 | 异常路径 | 异常分支双重覆盖不足 | 每个外部交互至少三条负面用例:空输入、错误凭证、中断 |
| T9 | 并发与竞态 | 时序交错串行碰不到 | 先验证"有无锁/队列"结构事实,再决定是否压测 |

## 工程与工具层

| ID | 技巧 | 失效 | 关键动作 |
|---|---|---|---|
| T12 | 回归墓碑 | 修过的 bug 复活是静默的 | 回归测试先在未修复代码上跑红,否则无证明力 |
| T13/T19/T22 | 环境一致性 | 测试结论在错误环境失效 | 解释器钉死到与生产一致;语法级检查也一样;权威门=与生产一致的运行环境全套重跑,本机只算冒烟 |
| T14 | 先测量后优化 | 性能直觉系统性失准 | 先加分阶段计时拿分布(中位数抗离群),再决定优化对象 |
| T15 | 敏感信息管理 | 日志/截图/临时文件是遗忘泄露面 | 画凭证值流向图,每个落点要么不持久、要么即用即删、断言只出布尔 |
| T16 | 工具限制隔离 | 把工具问题当 bug 修(或反之) | 替代路径验证(换驱动方式/人工操作)后再下结论,结论必须带证据 |
| T17 | 满屏滚动验证 | 全局裁剪样式静默截断内容 | 每页实测"滚到底+滚回顶",窗口调小复测,检查底部内容可交互 |
| T18 | 渲染取证 | 截图后端失真误导判断 | 截图异常先 DOM 取证:元素计数、路径属性长度、命中测试、画布解码像素 |
| T20 | 悬浮层遮挡裁剪 | 窄容器+长类目名冲突 | 逐条目悬停,断言悬浮层 ⊆ 宿主容器 ∧ ⊆ 视口;根治优先于悬停补偿 |
| T21 | 自动化直达 vs 用户路径 | 底层 API 短路了入口链路 | 涉及入口控件的用例一律从真实入口驱动,底层注入只做预置 |
| T23 | 共享临时目录清理契约 | 后到者的清理逻辑吞掉先到者产物 | 写入方用自属独立临时目录;契约测试断言"产物不在共享目录内" |
| T24 | 验证链依赖被修 bug | 修复后验证基建反向断裂 | 探测点用语义化端点;修状态码/语义类 bug 后 grep 全部消费方 |
| T25 | 链接穿透删除 | 递归删除沿链接/挂载点删空目标 | 清理前枚举链接只摘链接本身;跨 shell 拼命令先只读枚举确认 |
| T26 | 修复声明 vs 实现对照 | 声称的行为无实现或无测试锁 | 每条修复声明要 file:line 证据;共识只提升置信度,P0/P1 仍须可执行复现(见 severity.md) |
| T27 | 语法守卫目标解释器实测 | 守卫从未被喂过非法样本(假绿) | 守卫=子进程目标解释器+元测试自证+缺解释器显式 skip 告警 |
| T28 | 检出行尾漂移 | 同内容不同磁盘字节→门判定分裂 | 先比两个检出的内容摘要再下结论;行尾判定用多种手段交叉验证 |
| T29 | 死键裁决 grep 键名 | 只 grep 旧消费者文件名漏新读者 | 名字级全仓 grep + 枚举配置读取点 + 查契约测试锁定 |
| T30 | 验证车辆复刻运行形态 | 车辆失配→契约正确拒绝→假红 | 跑门前核对车辆清单(设备/加速器/数据卷/挂载或烘焙形态);重复性失败优先怀疑车辆 |

## 环境·构建·边界层

| ID | 技巧 | 失效 | 关键动作 |
|---|---|---|---|
| T31 | 状态外置 | 运行环境的生命周期短于它持有的数据时(容器、临时实例、可重装工作站),任何重建/替换都静默销毁数据 | 持久数据与运行环境生命周期解耦(外置存储);无法外置时,重建流程固定含「清点→备份→回放→对数验收」四步 |
| T32 | 产物≠版本库 | 构建产物固化的是本地工作区当时状态,不是版本库意图状态;工作区任何不洁(未提交/未刷新)都会进产物且构建不报错 | 构建前把工作区对齐到版本库并强制刷新可疑文件;产物正确性以产物自身实测为准,构建成功不构成验收 |
| T33 | 环境全要素复刻 | 预编译产物绑定构建环境的全要素(系统库/运行时/构建参数);只复刻部分要素时构建仍绿、运行才败 | 含二进制依赖的重建逐项复刻记录在案的环境要素;任一要素升级视为独立变更,带运行期验证 |
| T34 | 声明≠资源 | 依赖声明与依赖资源可用是两个独立前置条件;受限环境(离线/内网)里失败发生在资源侧,与代码无关 | 受限环境新增依赖前先确认资源可达;不可达时把新依赖与主代码库解耦安置 |
| T35 | 边界改写 | 参数跨工具/shell 边界时经历调用方预处理,可能被静默转换、丢弃,或因消费方提前退出而截断管道——命令成功≠语义按原意执行 | 跨边界调用先用只读探针确认参数到达形态;已知转换行为显式关闭或绕开;长驻进程避免接短命消费方 |
| T36 | 上下文绑定 | 执行上下文绑定其创建单元(线程/请求/会话);跨单元引用要到运行期才败,替身只复刻接口不复刻绑定关系,单测假绿 | 异步化/并发化改造的验证复刻真实执行形态(真实多单元);被迁移代码显式传递依赖,不依赖隐式上下文 |
| T37 | 多层解析 | 字面量每多经过一层解释器(shell/模板/宏)就被重写一次;内联越复杂、层越多,作者意图与实际执行的偏差越大 | 复杂逻辑移出多层解析位置,落为单层解析的独立文件随产物携带;必须内联时在目标层实测行为 |
