# 真实边界、影像、缓冲与空间链路

合成 fixture 可以确定性覆盖空态、NoData、容量和异常；实际遥感数据还会暴露 CRS、无效几何、来源路径、分辨率、影像覆盖和输入波段等问题。按用户范围采用代表性真实样例，不将单个矿山成功推广为全数据可用。

## 数据来源与准备

优先一手公开数据集，记录版本、URL、许可/署名要求、下载时间、SHA256、原始 feature ID 和 CRS。研究数据中的 mining footprint 不一定是法定矿权或当前开采边界；原几何只读保留，修复/转换形成派生文件并记原因。

检查几何类型、有效性、bounds、孔洞/多部件和坐标顺序。选择与产品目标相关的真实小样例，并按风险扩展到凹多边形、边缘跨瓦片或较大矿区；不为凑数量随机生成“真实边界”。

用户要求影像获取时，可按已有 [mine-imagery-gehi](../../mine-imagery-gehi/SKILL.md) 执行时间轴与 GeoTIFF 工作流；它不是本技能的硬依赖。工具缺失时核实已有便携包或在授权内使用任务目录，校验官方来源；不要修改系统环境或复制生产认证。

影像记录真实拍摄日期、覆盖率、获取方式、bounds、CRS、transform、尺寸、波段、NoData、分辨率和校验值。实际打开影像看空白、云/雪、拼接与矿区可辨性，同时以空间工具检查 geotag；图像清晰并不证明配准正确。Google Earth RGB 影像不等于多光谱模型所需波段，不假装缺失的波段或日期。

## 缓冲的两种含义

- **bbox 外扩**：下载窗口四边增加背景，用于影像覆盖；skill 的经纬度近似外扩不是矿山轮廓的精确 buffer。
- **多边形米制 buffer**：按实际边界进行空间扩张。验证实现是否转换到合适的米制 CRS/地理算法，不能直接对 EPSG:4326 的度坐标调用 `buffer(250)` 并声称 250m。

按项目支持范围选 0、常用距离、较大合法距离及错误输入，例如 0/100/250/500m。0 应保留原范围；正缓冲包含原边界，面积单调增加，米制外扩距离在算法/栅格容差内。用独立 GIS 运算或抽查距边界位置对照，记录 CRS 和误差，避免被测实现计算自己的期望值。

## 真实链路与检查

1. 实际导入边界，保留原 feature ID；登记真实影像，核对存储 key。
2. 通过实际 UI/API 选择矿山及缓冲距离执行裁剪；检查原图覆盖请求范围、不足覆盖时的明确行为、CRS/NoData/transform 与来源追溯。
3. 读取真实裁剪结果，再执行切片/后续消费；核对路径消费者可读、块数/尺寸、边缘覆盖、NoData 和实际产物。上一步失败就记链路阻塞，不私改路径让整链看似通过；可另开独立探针定位下游。
4. 若做瓦片，等待真实 worker 终态，激活后在浏览器显示真实瓦片、边界并操作缩放/点选；直接放置 PNG seed 只能验证下游渲染。
5. 推理/光谱仅在样例符合实际输入且依赖可用时执行。模型未实际运行则分类未验收；RGB 样例符合分类模型的波段、顺序和预处理契约时可以验分类。需要 NIR/SWIR 等波段的光谱指标，不能用 RGB 冒充；逐项标出缺失输入。GPU 与实际 CPU fallback 分别记录。

证据包按许可保留来源和署名，遥感文件/完整数据集不进入代码或 skill 仓库。公开报告可链接获准分享的派生截图；受限数据只给用户指定范围。
