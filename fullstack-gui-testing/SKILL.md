# 前后端与 GUI 深度验收

目标是确认用户能完成任务，并交付可复现证据。测试数量、HTTP 200、成功提示或脚本退出 0 都不能单独证明功能可用。

## 建立验收范围

先读取仓库规则、运行配置与相关契约，核对目录、分支、提交、未提交修改和实际运行版本。保护用户修改；只测试授权目标。按实际页面入口、路由、API 和文档列出功能，区分正常、空态、失败及有状态操作。

记录每项的 `passed / failed / blocked / skipped`，以及 `real / fixture / simulated`。分别注明服务保真度与数据真实性：真实服务处理合成数据不能称为真实矿山/影像验收。数据预置、替换边界及未运行依赖要明确；模拟 worker 不证明 GPU，SQLite 不证明生产数据库并发，截图不证明流畅。

准备独立账号、临时数据库/存储、可追踪的小数据和隔离端口；启动前检查配置是否仍指向默认生产资源。不要因审计改生产数据、安装系统组件或自动运行网上 skill 的脚本。现有授权内的可逆准备直接推进。

## 按任务闭环验证

1. 运行相关现有检查，保留真实退出码、计数、跳过原因和构建版本。按模块并行测试；同一 GUI 会话和性能采样由一个执行者负责。
2. 走真实链路：**用户入口 → 鉴权/请求 → 后端结果/任务终态 → 持久化重读 → 页面刷新重开**。后端细节见 [backend-api.md](references/backend-api.md)。API seed 可以准备下游状态，但不能替代待验收的创建、上传、保存按钮。
   用户要求真实数据或涉及 GIS 时，读取 [realdata-gis.md](references/realdata-gis.md)，核实真实边界、影像及米制缓冲；真实数据失败不能降级为合成数据后称通过。
3. 操作浏览器，保持上下文连续走关键流程，并覆盖快速切换、加载中切换、反向展开、重复提交、失败重试和重开。用语义定位、真实鼠标/键盘、条件等待；不要通过强制点击或修改组件内部状态掩盖不可操作。见 [gui-workflows.md](references/gui-workflows.md)。
4. 下载必须实际落盘、解析并核对当前来源版本。地图/画布必须在渲染后交互。保存成功必须重读；409/失败后检查原状态及未保存修改是否保留。
5. 截图后**实际打开查看**，记录裁切、遮挡、文字、颜色、画布及关键中间态。连续录屏/分阶段截图检查 motion；独立无录制样本测性能，见 [performance-evidence.md](references/performance-evidence.md)。浏览器不可用时继续独立测试，标记 GUI 阻塞，不能宣称已验收。

## 取证与交付

异常先分类为产品缺陷、测试缺陷或环境限制。报告每个缺陷的入口、操作、期望/实际、版本、可执行复现和证据；源码推测标为线索。没有授权修复时提交发现；修复时先复现，再重跑原路径与相关回归，不通过改预期、延长等待或盲目更新截图基线消除失败。

**已知 bug 必须出现在失败项中**，不能同时计为验收通过。区分“录制过程完成”与“被测行为通过”；即使退出码 0，也读取结果中的错误、已知缺陷、HTTP 失败和跳过项。最终只声明证据支持的范围，并交付截图、日志和未测项。认证文件、原始 trace 和业务数据可能含敏感信息；公开包使用合成数据并检查内容。

需要整理证据时，按 [evidence-format.md](references/evidence-format.md) 使用可选标准库助手：

```sh
python scripts/check-evidence.py /path/to/artifacts/evidence.json
```

它只校验记录一致性与文件存在，**不证明截图已被正确判断或产品无 bug**；诚实记录失败的报告也可以通过一致性校验。

现有 [high-intensity-testing](../high-intensity-testing/SKILL.md) 可补充代码审查；本技能可独立使用，无需先安装其他技能。纯函数单测或普通文案修改沿用最小验证，不强制全栈审计。
