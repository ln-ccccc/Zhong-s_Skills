# 交互、控制权与平台适配

## 信息架构与导航

根据 [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) 与 [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) 选择结构：顶层目的地用稳定导航，当前对象的操作用工具栏，少量同级内容用紧凑导航，复杂集合在空间足够时使用侧栏/列表/详情关系。不要把删除、上传等动作混进目的地标签。

显示当前所在位置，返回恢复原来的列表、筛选和阅读上下文。空内容解释原因，不让导航突然消失。跨窗口或设备调整结构时保留所选对象及任务，平台一致性指含义一致，不是所有屏幕像素完全一样。

[Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields) 强调可理解的搜索范围与有用结果。让人知道搜什么、如何清除/缩小范围；优先相关结果，保留筛选。实时搜索需处理异步过期、输入法组合输入与无结果状态，按现有服务能力实现，不强行添加搜索后端。

## 输入与纠错

依据 [Entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data)：能合理预填或选择就减少手输；支持粘贴、合适键盘与输入格式。保留可见标签，placeholder只作示例，不承担唯一字段名称。

验证帮助人完成任务，而不是惩罚输入中的半成品。按字段特性在离焦或提交时提示；错误靠近字段，说明哪里错、怎么改，并提供语义关联。提交失败保留输入，异步处理中防止重复写入，完成后明确结果。避免禁用按钮却不给任何理由。

## 反馈与恢复

[Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback) 的含义应落在任务附近：

| 状态 | 需要告诉人什么 |
|---|---|
| 默认/hover/focus/press | 能否操作、当前目标、输入是否被接收 |
| Loading | 哪一部分忙碌、能否继续其他任务、如何取消（仅业务支持时） |
| Empty | 为什么为空、可以做什么；区分无记录、无搜索结果和权限限制 |
| Success | 已完成什么，下一步或撤销入口 |
| Error/offline | 失败原因、数据是否保留、重试/恢复途径 |

可逆操作优先提供撤销；真正不可逆的行为明确后果并适度确认。撤销不是一段动画，需要实际数据合同支撑。禁止把模拟恢复当成生产删除恢复能力。

## Modality与焦点

[Modality](https://developer.apple.com/design/human-interface-guidelines/modality) 用于明确、专注的临时任务或重要决策。默认不要把所有详情变成弹窗，不层层打开嵌套模态。

模态必须有清楚标题、完成/取消/关闭路径，处理未保存内容；Web检查焦点进入、背景不可交互、Tab不进入背景控件、Esc和回焦。原生dialog保留浏览器工具栏的键盘通路，不为困焦屏蔽浏览器操作。非模态详情允许继续主任务，不困焦，隐藏内容不拦截输入。锚定入口能帮助理解来源，运动解释进入与离开，快速开关必须可打断。

## 输入方式与平台差异

下面是工程转译的选型表，不是统一尺寸规范：

| 平台/输入 | 保留的思想 | 调整方式 |
|---|---|---|
| 桌面鼠标/键盘 | 熟悉快捷路径、当前焦点与多任务上下文 | hover只是增强，完整Tab/键盘路径；窗口尺寸变化 |
| 手机触摸 | 可命中、手势有可见替代、任务连续 | 不依赖hover；安全区、软键盘与手指遮挡；按目标平台检查命中尺寸 |
| 平板/多窗口 | 同一对象的浏览与编辑连续 | 可在列表/详情和紧凑导航间适配，保留选择 |
| 电视/遥控器 | 远距离阅读、清楚焦点与方向移动 | 更强空间层级，按观看距离而非照搬手机字号 |
| 空间/眼手输入 | 稳定目标、可理解深度与舒适性 | 遵循目标系统的空间/输入规范；不模拟鼠标hover当成眼动支持 |

原生优先系统组件及平台当前规范；Web用语义HTML、浏览器可用能力与渐进增强。视觉反馈、音效和真实硬件触觉相互补充，不互相冒充。只有任务要求支持的平台进入实现与验收，不自动扩大到全部设备。

## 从理念到具体设计

1. 写出一个主要任务与失败/恢复路径，例如阅读收藏、购买结算、设置保存或数据核查。
2. 选合适信息结构与平台组件；保留既有品牌、术语和业务合同。
3. 列出本次涉及的状态，配套视觉、语义和motion；材质不得妨碍输入/阅读。
4. 以真实任务验收，分别记录可用性、视觉、性能和未测试辅助输入。不要用“像Apple”作为唯一判断。
