# 浏览器验收与效果选择

## 运行

演示可直接用浏览器打开 `assets/demo/index.html`。先进入实际skill目录（仓库中为 `apple-interface-design/`；安装后的路径可能不同），再执行：

```bash
npm ci
npm test
npx playwright install chromium
npm run test:browser -- --out ./artifacts/apple-glass
npm run test:reader -- --out ./artifacts/reader
```

已有Playwright和浏览器时不需要重新安装；通过 `PLAYWRIGHT_MODULE_PATH` 指向已安装的Playwright入口，或使用skill目录安装的依赖。两个脚本支持 `--browser /path/to/browser`、`--headed`；`--out` 保存JSON及截图。材质演示另支持 `--demo /path/to/index.html` 指定副本。它们只打开独立浏览器测试演示，不连接业务服务，不修改真实项目。

CI headless用于功能回归；视觉与卡顿结论需要在 headed 目标浏览器实际观察。安装浏览器及其系统依赖前遵循环境权限规则。浏览器不可用时继续静态/单元检查，但不能宣称GUI验收通过。

## 连续序列

在目标PC窗口尺寸依次运行：

1. 切换主题及三种材质，检查浮动控件与正文的分离，查看图片是否完整且未失真。
2. 概览→影像→报告连续快切至少20次；加载期间切换，最终选中项与内容一致，无旧请求回写。
3. 实际点刷新：出现局部加载、完成状态；尝试失败再重试，重复触发不留下卡死按钮或重复面板。
4. 多次展开/收起详情，Tab和Esc按语义处理。关闭后隐藏内容不能进入键盘序列；非模态不困焦。
5. 系统减少动态效果、手动减少透明度、系统减少透明度、增强对比、无blur支持分别检查。降低效果后内容、状态和按钮操作不丢失。
6. 检查1440×900与1920×1080，以及200%缩放或等效缩小CSS视口。脚本分别使用CSS `zoom:2`压力测试与720×450等效CSS视口；CSS zoom不等于浏览器原生缩放，也不会改变viewport媒体查询。检查地图内图例/署名不相交；表格可滚动，页面关键控件不能消失。SVG/栅格图不改纵横比。

脚本覆盖演示合同；接入项目需根据实际控件和网络改成对应流程，不能只运行此demo后声称整个应用无bug。

阅读示例另检查1100×900、390×844与CSS放大：搜索范围/空态、24次阅读返回、逐次撤销恢复排序、阅读中改变收藏、模态Tab/Esc回焦、取消草稿、错误提示与输入保留、保存忙碌状态、正文字号和动态/透明度偏好。窄视口是桌面浏览器模拟，不能当作手机硬件验收；44 CSS px是本示例的命中区域目标，不是所有Apple平台的统一规范。截图应检查阅读节奏与设置窗口，而不是要求所有产品复用仪表盘。

## 可读性与性能

`scripts/contrast.mjs` 合成材质与黑白背景后计算sRGB WCAG对比。只适用于输入已解析的RGB(A)，用于示例的保守检查；不处理混合模式、任意图片、空间渐变与所有伪元素。实际复杂底图仍需要截图、颜色采样或专业对比工具，不等于完整WCAG认证。

帧采样使用前台页面 `requestAnimationFrame` 的间隔；超过50ms的间隔记为明显停顿候选，报告p95和样本数量。采样等待有12秒Node侧超时，页面停止绘制时明确失败并保存报告；运行headed时保持窗口前台。这是本次同机比较门，不是Apple规范或GPU帧时间。测试机器负载、刷新率和渲染方式会影响结果，不能把headless数据称为生产60fps保证。若持续偏高，先减少blur面积、叠层和动效，再在目标设备复测。

先排除功能、可达性和可读性失败，再选择效果。极透明方案看起来更“透”也可能使控件受底图干扰；实色清晰但失去部分背景关联；均衡方案只有通过实测后才适合作为默认。保存各方案相同视口/主题的截图及数据，注明选择理由。

## 必须报告的限制

说明浏览器/系统、headed或headless、尺寸、测试内容和未测平台。模拟数据加载不能覆盖生产网络、长时间GPU负载、真实LED/投影、Safari/WebKit等未测环境。遇到缺口保留待办，不以静态源码检查替代运行证据。
